# Outfit App — 画面・UX設計 v1.1

## 体験原則
- 毎朝の操作はゼロ〜1回を目標。「今日の服」→必要なら「これを着た」。強制的な気分入力・長文説明なし。
- モバイルファースト、白〜オフホワイトの背景、写真が主役。CTAは1画面に主要1個。控えめな差し色。PCは幅制限の2カラム。
- スマホ下部タブ：今日 / 1週間 / クローゼット / 記録 / 設定。欲しい服はv0.2で追加。
- 服写真のトリミング・背景除去なし。サムネのcontain表示で全体を見せる。背景色は統一。

| `/today` | 今日 | 服のカード、理由一言、天気警告、着用確定、再提案（残回数） |
| `/week` | 週間 | 出勤予定、7日カード、固定/暫定表示、週2回の全体再生成 |
| `/week/[date]` | 日の編集 | 気分・特別予定・服入替・手動固定・例外勤務 |
| `/closet` | クローゼット | 種類フィルタ・利用可否・100着残数 |

## 初回フロー
1. アカウント作成（Googleまたはメール）→メール認証が必要な場合は完了案内。
2. 初期設定は3ステップ：勤務・祝日 / 地域・調整時刻 / 好み・職場ルール。スキップ可能項目を明示。
3. 服のアップロード画面で上1・下1以上で「まず試す」を有効化。5〜10着の登録を穏やかに推奨。靴・アウター未登録でも進める。
4. AI分類が終わった服は自動保存して一覧へ反映（判定不明は要修正バッジ）。初回週間計画を生成し、/todayへ。

## 毎朝フロー
1. `/today`に「今日の服はこれ」を表示。状態：確定 / 暫定（天気未取得） / 不足あり / 予定手動固定。提案理由は1行。
2. 『これを着た』→確認済みの服をwear_logsへ記録。同日再押下で二重計上しない。
3. 『別の服にする』→任意で理由のチップを選択（着たくない・もっとカジュアル・別の組み合わせ）→残り3回/日の範囲で生成。
4. 登録服を自分で入替えた場合、その日を手動固定に変更。天気が変われば注意を表示するが上書きしない。

## 週間フロー
- 日曜夜に来週のコーデを暫定生成、出勤日だけ表示。雨・気温・出勤日例外・洗濯情報が変われば影響する自動提案だけ調整。
- 週間全体手動再生成は週2回まで。個別日の手動編集はこの枠を消費しない。
- 祝日設定が休みなら対象外。ただし当該日だけ出勤へ変更可。

## 主な画面状態と文言
- `loading`: 「今日の服を確認しています」＋既存の週間計画を残す。
- `ai_unavailable`: 「現在は簡易提案でご案内しています」＋AIなしの候補。
- `weather_stale`: 「最新の天気が取得できないため、参考の服装です」。
- `insufficient`: 「アウターが未登録です。寒い日は追加の防寒着をご確認ください」。
- `laundry_blocked`: 「今週の服が足りません。洗濯済みへの変更か服の追加をお願いします」。
- `quota_hit`: 「今日の作り直しは3回までです」。
- `storage_limit`: 「現在、新しい写真の登録を一時制限しています」。

## デザイン指針
- シンプル＋ファッション性。本文16px以上、タップ領域44px以上を目安。キーボード・読み上げ対応。服のaltテキストは種類＋色で生成し、修正可能。
- 着用回数や登録上限を押し付けないが、誤操作を防ぐ削除確認・Undoを用意。
- 初回コーデ成功、服を登録するまでの所要時間、翌週再訪率を集計。ログインID・メール・写真本体・地域の細かな情報を外部分析サービスへ送らない。匿名化は単なるID置換で済ませず、個人を再識別できない集計を基本とする。


## 認証UI・退会UIの追加制約
- サインアップ時はメールアドレス＋パスワード、または「Googleで続ける」のみ。氏名・ニックネーム・生年月日・電話番号などの任意入力欄を設けない。
- メール認証・パスワード再設定はSupabase Authのフローへ誘導し、自前のパスワード保存・照合をしない。エラー表示に登録済みメールの存在を過剰に明かさない。
- 設定画面にメールを表示する場合は認証済みセッションからその都度取得し、アプリの`profiles`へコピーしない。
- 退会は再認証またはセッション再確認と明示的確認を必須とし、処理中・完了・失敗（問い合わせ案内）を表示する。
