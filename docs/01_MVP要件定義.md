# Outfit App — MVP要件定義 v1.1
作成日：2026-10-11。企画名は仮称。対象：日本国内、日本語、私服勤務で毎朝の服選びに判断力を使いたくない人。Web/PWA、スマートフォン優先、PC利用も可能。MVPは完全無料で一般公開、月額運用目標3,000円以下（厳密保証ではない）。

## プロダクトの約束
「登録済みの服から、仕事に着ていく服を原則1コーデ決める」。毎朝の入力を必須にしない。誰が見ても1画面目に『今日の服』と『これを着た』があり、理由は一言のみ。普段のコーデの重複を抑え、天気・会社ルール・着用可否を守る。

## MVP v0.1（初回公開）
- メール＋パスワード、Google OAuthによるサインイン。認証処理・メールアドレス・パスワードハッシュ等はSupabase Authに委任し、アプリ独自DBに複製しない。メール確認・再設定・退会・個人データ消去に対応。
- 新規登録・再設定のパスワードは8文字以上、英小文字・英大文字・数字・記号を各1文字以上必須とする。文字種の定義は08に従い、Supabase Auth側でも強制する。ログインに新しい強度条件を適用せず、既存パスワードでの認証を妨げない。
- 初回設定：基本の出勤曜日、祝日休みオン/オフ、地域、会社の服装ルール・NGカテゴリ、好み。初回2着（トップス1/ボトムス1）から試せる。5〜10着を推奨。
- 1ユーザー最大100着。写真を1着ずつアップロードし、構図を変えずにWebP等で圧縮。AIが種類・色・季節を分類、自動保存。後から修正可能。生地の厚さ（薄手/普通/厚手）は任意。
- AIがトップス・ボトムス・靴・アウターから必要なものを選ぶ。未登録カテゴリは不明と明示。会社のNG・利用不可の服は採用しない。ユーザーの気分指定（任意）も反映。
- 初回設定後に1週間の計画を生成。毎週日曜夜に翌週の計画を自動更新し、毎朝ユーザー指定時刻までに最新の気温・雨で必要時のみ再調整。先の日付の予報は暫定。特別な仕事予定は任意指定。
- 出勤日の基本設定を繰り返し、週ごとの休暇・在宅・休日出勤を上書き可能。日本の祝日を休みにするか設定し、祝日単位の例外も可能。
- その日のAI提案の手動再生成は1日3回まで、週間計画の手動全体再生成は週2回まで。ユーザーが手動で編集した日はAIが上書きしない。天候・洗濯に合わなければ警告する。
- 『今日これを着た』で実績確定（提案だけでは着用済みにしない）。服を変更してから確定可能。実績から好みと着用回数を更新。種類別の洗濯までの着用回数の初期値を持ち、ユーザーが変更可能。洗濯済みをワンタップで戻す。
- 同一コーデの連続をできるだけ避けるが、服が少ない場合は重複を許容する。洗濯回数の上限と職場ルールは優先。
- 服の追加/削除/洗濯状態変更に影響を受ける**自動生成の**日だけ再評価。ユーザーが手動で固定した日のコーデは警告のみ。
- AI上限到達・障害時には登録済みのメタデータでルールベースの簡易提案。写真分類のAIが使えなくても手動で種類・色・季節を選び登録できる。
- 天気API不調時は鮮度を示したキャッシュ予報を利用。古すぎれば季節ベースの暫定提案と注意表示。
- 選んだ理由は一言のみ。暑がり/寒がり設定・体感フィードバックは提供しない。

## v0.2（合意済み後続機能）
- Webプッシュ（対応ブラウザ・端末条件あり）またはメール、両方、オフを選べる。通知時刻はユーザーが設定。
- 欲しい服リスト：写真・名前・URL・メモ。
- コーデ画像を生成し、X/Instagramに共有（ブラウザ・OSの共有機能／画像保存の代替あり）。公開コーデページ・OGP付きURL・アプリ内SNSは対象外。

## 非対象（初期）
ネイティブアプリ、バーチャル試着、EC決済、Googleカレンダー連携、個人の暑がり/寒がり、服素材の詳細、バックグラウンド位置情報、公開SNSフィード、英語対応。将来拡張できるように項目と責務は分離する。

## 制約・受け入れ条件
- ユーザー認証なしの画像閲覧不可。MVPは画像共有そのものが後続段階であり、初回公開時の服画像は非公開。退会時は画像・DB・認証情報・通知トークンを消去する。バックアップ内の残存期間を利用規約で明示。
- 基本動作は「提案→着用確定→洗濯状態反映→翌日の提案」。リロードしても重複ログが付かない。
- AIがDBに存在しない服IDを返しても採用しない。使用不可やNG服を含む場合は再選定する。
- 全体上限に達したらAIの新規実行を停止し、非AI提案。インフラ/認証メール/ストレージの無料枠の上限も監視し、必要なら新規登録・画像追加を一時制限する。一般公開は無制限の容量保証を意味しない。


## アカウント情報最小化（追加確定方針）
- 独自DBには氏名・生年月日・性別・住所・電話番号・パスワード・Googleのアクセストークンを保存しない。`user_id`（Supabase AuthのUUID）でサービスデータを関連付ける。
- メールアドレスは認証のためSupabase Auth側に保存される。運営側の責任や漏えいリスクがゼロになるわけではない。認証方式（メール＋パスワード、Google）は質問11の合意どおり維持。
- 服の写真・地域・好み・着用履歴は、本人に紐づくサービスデータとして継続して安全管理する。写真や着用履歴をブラウザ端末内のみに限定する設計へは変更しない。
- 個人データの外部送信先・利用目的（OpenAI画像解析、天気取得、メール認証等）をプライバシーポリシーに明示する。認証・服画像・APIの権限チェックを公開前必須とする。
